# Contribution

Contributions are very much appreciated, but in order to keep a standard, contributor must follow a set of rules.

## The Rules

1. For wallpaper naming, [naming format](#naming-format) should be followed
2. If the wallpaper is Ai generated or upscaled, then it should be mentioned if known
3. Only artist watermark/signature are allowed if present
4. wallpapers should be in `png` or `jpg`
5. The resolution must be at least 1080p resolution

## Contribution Methods

### Standard method

1. Fork the repository
2. Go to the folder `collection 5` on `main` branch
3. Add your wallpapers there
4. Stage, commit, push
5. Open PR with structured description of what u have done, and wait for it...

### If you don't want to fork the entire repo

1. Go to [wallpaper-suggestions](https://github.com/Firefly-SL/wal-collection/discussions/1)
2. Draft a comment in this format
   - the image link should lead to the image not the website
   - image extension can be ignored if not known or doesn't match the rules

```txt
1. [yourname-blue1.png](example.com/img1)
2. [yourname-blue2.png](example.com/img2)
3. [yourname-red1.png](example.com/img3)
```

## Naming Format

> [name]-[color]-[extra][count]

- **name**, your GitHub username is recommended
  - keep it short and lowercase (Firefly-SL to firefly)
  - use the same name for all your wallpapers in the collection
- **color** is the primary color in the image
  - use basic color name (red, brown, green, etc..)
  - don't use complex color name (light green, sky blue, dark red, phlox, etc.)
- **extra** `optional`, only uses if the wallpaper is Ai generated or upscaled
  - for Ai generated use extra as `ai`
  - for upscaled use extra as `upscaled`
- **count** is the number added at the end of the filename to overcome duplication issue
  - it is mandatory, even if there is no file with similar name
  - it follows with **color** in name, ignored **extra**

```txt
firefly-blue1.png
firefly-brown1.png
firefly-ai-brown2.png
firefly-brown3.png
```
